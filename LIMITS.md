# LIMITS

- Vault — dev-режим (данные в памяти), не persistent. Для прода — Vault с storage backend (вне рамок теста).
- DLQ / лимит повторов для worker — не реализовано (L3).
- `provider.py` использует `verify=False` — не исправлено (L3).
- `request_id` в логах api/worker — не реализовано (L3).
- RED/бизнес-метрики, алерты, мета-мониторинг, дашборд — L4.
- `reporting-ui` не подключён к деплою (L4).
- `compose-smoke` в CI проверяет стек без Vault (SECRETS_SOURCE=env).
- Образы в GHCR — **публичные** (тест). В проде: приватные + pull secret / IAM.
- `push` в CI — `GITHUB_TOKEN`, без отдельного robot-аккаунта. В проде — отдельный токен с минимальными правами.
- `compose-smoke` пуллит образ по sha текущего коммита; если пакет GHCR ещё не создан (первый прогон) — push создаёт его, smoke пуллит. Первый прогон может требовать «сделать пакет публичным» вручную (GitHub UI) — отмечено в README.
- Нефиксимые CVE в `python:3.12-slim` (Debian 13.7): `util-linux`, `ncurses`, `sqlite`, `systemd`, `perl-base` — без фикса на момент скана; не блокируют (политика `--ignore-unfixed`), но требуют мониторинга и обновления base.
- `zlib1g` — fixed, но base не подтянул; `build --pull` может решить; иначе ждём обновления `python:3.12-slim`.
- `starlette` — обновлён до `X`; если остались CVE (например, при `0.49.1` вместо `1.3.1`) — записать, до миграции на 1.x.
- Trivy `v0.57.1` пинован; база CVE обновляется (mirror.gcr.io), в проде — регулярное обновление.
